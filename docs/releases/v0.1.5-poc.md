# v0.1.5-poc

> Experimental pre-release. Read the safety notes and run the read-only checks before using administrator privileges.

This release is the first live-validated proof of concept for temporarily passing the macOS-side iPhone Mirroring eligibility check in the tested EU configuration. It does not disable SIP, spoof Core Location, install a daemon, or leave its plist patch behind after a temporary launch.

## Validated behavior

- Tested on one Apple-silicon Mac running macOS 27.2 and one iPhone running iOS 27.
- A 30-second guarded temporary launch completed first pairing and displayed the iPhone.
- The helper then removed the temporary `uchg` flag, restored the original plist, and verified restoration while the active Mirroring session continued.
- No phone-side `SFAuthenticationErrorCodeRegionLocked` (`Code=35`) appeared in the successful captured test.
- Unlocking the iPhone ended the session normally. A later Retry was a new eligibility attempt after restoration and could fail against the original Mac-side state.

This is one confirmed configuration, not a compatibility guarantee. Apple can change the private eligibility format or handshake at any time.

## Recommended first run

```sh
./mirror-eu doctor
./mirror-eu launch --guard-recompute --hold-seconds 30 --dry-run
sudo ./mirror-eu launch --guard-recompute --hold-seconds 30
```

Type `LOCKED-LAUNCH` only after reviewing the printed plan. If a later reconnect or Retry fails after the original plist has already been restored, quit iPhone Mirroring and start a new temporary launch.

## Safety model

- complete private backup plus SHA-256 manifest before every write;
- atomic same-directory replacement;
- validation of schema, content, ownership, mode, flags, ACLs, and extended attributes;
- automatic restoration after temporary launch;
- explicit confirmation for every write;
- no SIP changes, Core Location changes, `locationd` restart, daemon, login item, or system-immutable flag;
- bounded and redacted diagnostics;
- fail-closed behavior for unknown or concurrently changed state.

The optional guard uses only the user-immutable flag for at most 30 seconds. A sudden power loss or `SIGKILL` can prevent cleanup, so the helper prints an exact emergency recovery command before applying it.
